# PDF 转 Markdown 质量检查 Skill / SOP

## 1. Skill 名称和适用场景

名称：PDF to Markdown Review Skill

适用场景：

- 已有 PDF、Markdown、结构化 blocks/tables、解析日志，需要先做一轮质量检查。
- 需要判断 PDF 是否有文字层、是否需要 OCR、页码和 source locator 是否可追溯。
- 需要复核标题、正文、表格、脚注、图片页、扫描页、关键数值和合计数。
- 需要给 RAG、检索、智能体处理或人工复核交付一个风险清单。

目标：减少重复人工检查，把常见问题自动标记出来，但不声称可以替代人工复核。

## 2. 不适用或必须人工介入的场景

- 扫描件、图片页、手写批注、低清晰度票据：必须人工抽查，OCR 只能作为候选。
- 合同、审计报告、财报等高风险文档：关键金额、日期、主体、条款必须人工复核。
- 表格存在跨页、合并单元格、多层表头、旋转页面、复杂脚注：自动结果只作为初稿。
- PDF 与外部 GT/Excel/数据库不一致：不要自动改写 final_gt，应标记 `NEED_RECHECK`。
- 无法提供原 PDF 或 source locator 缺失：不能视为可追溯结果。

## 3. 输入文件要求

- 原始 PDF：用于抽查页面图像、页码、标题、表格边界和扫描页。
- Markdown：应保留 `<!-- page: n -->` 页码标记、标题、正文、表格和扫描页提示。
- 结构化 blocks/tables：至少包含 page、type、text、bbox/source locator、表格行列。
- 解析日志或 QA 报告：包含解析器版本、失败页面、OCR 状态、警告和错误。
- 可选 GT 文件：Excel、人工标注、数据库导出或历史 final_gt，用于数值和字段核对。

## 4. 输出格式

输出 `qa_report.md` 或同等结构化报告，包含：

- 总览：文件名、页数、解析器、块数量、表格数量、扫描页数量。
- 问题清单：按严重级别列出 page、source locator、问题描述、建议动作。
- 需人工复核清单：扫描页、低置信 OCR、表格错位、合计不一致、来源缺失。
- 优化建议：解析规则、OCR、表格抽取、bad case 回归用例。

建议严重级别：

- `ERROR`：页码缺失、表格合计错误、关键字段来源缺失、明显乱码。
- `WARNING`：疑似扫描页、表格行列不齐、跨页表格、OCR 低置信。
- `INFO`：可接受但建议抽查的问题，例如页眉已移除、脚注保留策略。

## 5. 执行步骤

1. 检查文件完整性：确认 PDF、Markdown、blocks/tables、日志都存在，记录解析器和运行时间。
2. 检查页码覆盖：Markdown 中每页应有 `<!-- page: n -->`，页码数量应与 PDF 页数一致。
3. 检查标题层级：抽查 `#`/`##` 是否来自正文标题，不应把页眉、表题误判为主标题。
4. 检查正文连续性：检查空页、乱码、异常断行、页眉页脚污染、重复段落。
5. 检查表格：核对表题、表头、行列数、空单元格、跨页延续、单位和脚注。
6. 检查数值：对存在“合计”的表格校验明细之和；注意小数、负数、千分位和单位。
7. 检查图片/扫描页：文字层过少或只有页脚时标记 `needs_ocr: true`，要求人工查看原图。
8. 检查来源追溯：每个重要块和表格都应有 page 和 bbox/source locator。
9. 形成报告：按严重级别排序，给出人工复核动作，不直接修正无法证明的内容。

## 6. 质量检查 Checklist

- 页码：页码标记完整、顺序正确、无重复、无缺页。
- 标题：层级合理，附注/章节标题没有被页眉或表题污染。
- 正文：没有大段乱码、重复、漏行、异常空格或无意义换行。
- 表格完整性：表题、表头、所有明细行、合计行、备注列均保留。
- 行列结构：列数一致，长文本没有被拆成错误行，空备注不应导致列错位。
- 数值：小数、负数、千分位、百分号、单位保持；合计数可自动校验时必须校验。
- 单位：金额单位、币种、期间、口径说明保留。
- 脚注：脚注和补充说明保留，并与相关表格或页面关联。
- 扫描页：识别无文字层或低文字层页面，标记 OCR 状态和置信度。
- source locator：重要内容都有 page、bbox 或原始行列定位。

## 7. 常见错误和处理方式

- 页眉污染：把固定页眉识别为 header，从 Markdown 正文移除，但在 blocks 中保留可追溯记录。
- 页脚污染：页脚不要进入正文；页码用统一注释保留。
- 表格错位：检查行列数、数值列位置、备注列是否漂移；标记人工复核。
- 跨页表格：检测下一页是否缺表题但延续相同表头，使用同一 table_id 并记录页码范围。
- OCR 低置信：保留 OCR 文本候选，标记置信度和原图路径，不写入 final_gt。
- 乱码：记录页码和 bbox，尝试换解析器或字体编码策略，无法确认时人工复核。
- 空页：区分真实空白页、图片页、解析失败页；解析失败不得当作空白。
- 图片说明缺失：检查图片附近 caption；无文字层时标记需要人工补充。
- 表格标题丢失：用表格上方最近的 `表x-y` 或明显 caption 补关联，不确定时标记。

## 8. 人工复核点

- 扫描页、图片页、OCR 低置信页面。
- 关键金额、日期、主体名称、期间、单位和脚注。
- 合计不一致、表格行列不齐、长文本拆行、跨页表格。
- PDF 与 Excel/GT 不一致的字段。
- 任何缺少 source locator 的重要内容。

## 9. 持续优化方式

- 每次发现 bad case，记录原 PDF 页码、错误 Markdown、错误 blocks、期望结果和修复策略。
- 把可自动判断的问题写成检查规则，并加入回归样例。
- 把不可自动判断的问题写入人工复核 checklist，避免智能体盲改。
- 定期统计错误类型：扫描页、表格错位、OCR、页眉污染、合计错误，优先优化高频问题。
- 保留 Git diff 和 review 记录，所有规则变更都要能解释触发条件和风险。

## 10. 小示例

输入 Markdown：

```md
<!-- page: 1 -->
**表36-1 租赁负债到期分析**

| 项目 | 2026-06-30 | 2025-12-31 |
| --- | --- | --- |
| 一年以内 | 120.50 | 110.25 |
| 一至两年 | 88.00 | 91.00 |
| 两至五年 | 160.75 | 149.30 |
| 合计 | 369.25 | 350.55 |
```

输出质量判断：

- `INFO`：页码标记存在，表题存在，表头包含两个期间列。
- `INFO`：2026-06-30 合计校验通过，120.50 + 88.00 + 160.75 = 369.25。
- `INFO`：2025-12-31 合计校验通过，110.25 + 91.00 + 149.30 = 350.55。
- `RECHECK`：仍需抽查原 PDF，确认金额单位和表格脚注是否完整保留。
